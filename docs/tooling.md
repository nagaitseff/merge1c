# Выбор инструментов и подходов

Инструмент включается в библиотеку, если решает конкретную задачу и его результат можно проверить. Удобный просмотр diff, синтаксический анализ и правильное объединение формы — разные задачи.

## Утилиты для повседневной работы

| Утилита | Для чего полезна | Роль в проекте |
|---|---|---|
| [ripgrep / rg](https://github.com/BurntSushi/ripgrep) | Быстрый поиск текста | Уже доступен; используется при разработке |
| [ag](https://github.com/ggreer/the_silver_searcher) | Поиск текста | Пока не нужен: эту задачу выполняет rg |
| [fd](https://github.com/sharkdp/fd) | Поиск файлов | Необязательное удобство навигации |
| [fzf](https://github.com/junegunn/fzf) | Интерактивный выбор из списка | Возможный интерфейс выбора конфликтов в будущем |
| [bat](https://github.com/sharkdp/bat) | Просмотр файлов с подсветкой | Необязательный просмотр |
| [delta](https://github.com/dandavison/delta) | Читаемый вывод diff | Необязательное средство ревью |
| [jq](https://jqlang.org/manual/) | Выборка полей JSON | Удобен для отчётов; PowerShell также умеет ConvertFrom-Json |
| [Difftastic](https://difftastic.wilfred.me.uk/) | Сравнение с учётом синтаксиса | Возможное дополнительное средство просмотра |

Перечисленные программы не становятся обязательными зависимостями merge1c. Встроенный обход файлов не заменяется вызовом rg или fd: фильтры скрытых и игнорируемых файлов не должны убрать ресурсы из результата. Измерения не показали необходимости скачивать этот набор для работы ядра.

## Синтаксическое объединение

[Mergiraf](https://mergiraf.org/) использует дерево исходника и отдельные настройки языка. Для формы особенно важны идентичность элементов и допустимость изменения их порядка. Порядок дочерних элементов интерфейса нельзя считать произвольным только потому, что XML удалось разобрать. Список поддержанных языков Mergiraf содержит XML; это не подтверждение поддержки правил ID и ссылок формы 1С.

[Difftastic](https://github.com/wilfred/difftastic#can-difftastic-do-merges) помогает увидеть структурные изменения, но сам не выполняет merge. Поэтому он может дополнять ручной просмотр, а не подтверждать правильность кандидата.

[GumTree](https://github.com/GumTreeDiff/gumtree) полезен как источник алгоритмов сопоставления деревьев и перемещений. Для нашего процесса дополнительно нужны правила идентичности объектов, согласования ID, сохранения байтов и проверки всей конфигурации.

Практический вывод для merge1c: сравнивать структуру, изменять только необходимые диапазоны исходника, явно описывать порядок и ключи коллекций, проверять результат независимо. Сложное совпадение не следует считать доказанным только по внешнему сходству.

## Анализ BSL

[BSL Language Server](https://github.com/1c-syntax/bsl-language-server) — кандидат на независимую внешнюю диагностику BSL. Перед подключением нужно выбрать конкретную версию, необходимые диагностики и протокол результатов, проверить требования Java и стоимость запуска на большой выгрузке. Он не подключён и не скачан автоматически; проверка настоящей платформой остаётся отдельным этапом.

## Проверка нашего Python-кода

Для статической проверки установлен [Ruff](https://docs.astral.sh/ruff/installation/) 0.17.2 из официального PyPI в отдельный каталог инструментов разработки. Его версия и правила зафиксированы в настройках проекта. Обязательные зависимости самой библиотеки остаются пустыми.

Помимо линтера используются самостоятельные регрессии, сравнение нового алгоритма с простой эталонной реализацией, проверки идемпотентности, точных байтов и настоящих временных репозиториев. Измерения скорости не подменяются хрупкими требованиями «тест обязан уложиться в N миллисекунд».
