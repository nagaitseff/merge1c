# Разработка и выпуск версии

Пользовательский порядок работы описан в [руководстве](guide.md). Этот файл нужен разработчику библиотеки.

## Окружение и обязательные проверки

```text
python -m pip install -e ".[dev]"
ruff check src tests examples scripts
python -m unittest discover -s tests -q
```

Рабочая библиотека использует стандартную библиотеку Python. Ruff 0.17.2 — отдельная зависимость разработки; правила зафиксированы в pyproject.toml. Тесты работают со своими временными каталогами и репозиториями. На Windows дополнительно вызываются доступные PowerShell 5.1, PowerShell 7 и cmd. Отсутствующая оболочка пропускается.

Синтетический пример: `python examples/demo.py`. Замеры: `python examples/benchmark.py --records 1000 5000`. Время и tracemalloc измеряются отдельно, потому что трассировка замедляет выполнение. В тестах нет хрупкого требования уложиться в N миллисекунд.

## Собрать поставку

Из корня проекта, где лежит pyproject.toml, выполните в cmd или PowerShell:

```text
python -m venv .venv-build
.venv-build\Scripts\python.exe -m pip install -r scripts/requirements-build.txt
.venv-build\Scripts\python.exe scripts/build_release.py --windows
.venv-build\Scripts\python.exe scripts/check_release.py
```

В PowerShell путь в кавычках запускается через `&`; приведённые относительные пути без пробелов можно вводить как есть. Интернет нужен для первоначальной установки инструментов. Отдельный компилятор C/C++ для этой сборки не требуется. Скрипт запускается на Windows и выпускает:

- `dist/merge1c-0.1.2-py3-none-any.whl` — библиотека и CLI для установленного Python;
- `dist/merge1c-0.1.2.tar.gz` — исходники, тесты, документация и скрипты сборки;
- `dist/merge1c-0.1.2-windows-x64/merge1c.exe` и `_internal` — переносимая папка для Windows x64;
- `dist/merge1c-0.1.2-windows-x64.zip` — эта же папка в архиве;
- `dist/SHA256SUMS.txt` — контрольные суммы файлов поставки.

Пакет без Windows-поставки: `.venv-build\Scripts\python.exe scripts/build_release.py`. На Linux/macOS создаются только wheel и архив исходников. Разрядность Windows-поставки определяется Python сборки; для x64 нужен Python x64. После изменения исходников повторите сборку: файл wheel и exe сами не обновляются. Старые версии скрипт не удаляет; перед выпуском проверьте содержимое dist.

Версии в pyproject.toml и `__version__` должны совпадать, иначе сборка останавливается. Скрипт проверяет наличие TOML-шаблонов внутри wheel и запуск собранного exe. PyInstaller собирает программу в папку: каталог `_internal` обязателен. Такой режим не требует прав на распаковку программы в TEMP при старте. [Документация PyInstaller](https://pyinstaller.org/en/stable/operating-mode.html) объясняет состав папки и отличие от onefile; [PyPA](https://packaging.python.org/en/latest/tutorials/packaging-projects/) описывает wheel и исходный архив.

`check_release.py` проверяет готовые артефакты на Windows: устанавливает wheel в своё чистое окружение, запускает модуль и pip-запускатель, распаковывает ZIP, проверяет exe в cmd и PowerShell без Python в PATH и с недоступным TEMP. Затем готовит Git-слияние, запускает внешний валидатор и создаёт проверочную ветку. После проверки удаляет собственные временные каталоги. Git должен быть установлен; пользовательские репозитории не используются.

## Компоненты

| Модуль | Ответственность |
|---|---|
| config.py | Строгий TOML, профили, локальные переопределения, снимок настроек |

| workspace.py | Выбор каталога сессий и реальные проверки файловых операций |

| session.py | Снимки, блокировка, ручные решения, отчёты и актуальность проверок |
| processes.py, tools.py | Запуск внешних программ с отдельными аргументами и протоколом результатов |
| cli.py | Команды, прогресс и вывод для человека или автоматизации |

## Гарантии, которые нельзя ослаблять

XML записывается правками диапазонов исходного incoming; документ не пересериализуется целиком. Метаданные сопоставляются по контейнеру, виду и собственному UUID. Похожие XML-обвязки не доказывают идентичность объектов.

Числовые ID формы относятся к разным областям. Свободные значения сохраняются. Неизвестная ссылка при переназначении означает неразрешённый случай. Неоднозначное перемещение или совпадение не должно превращаться в успех только из-за корректного синтаксиса.

Проверяется всё выбранное дерево результата, а не только конфликтовавшие файлы. Событие XML и процедура BSL могут отдельно объединиться без конфликта, но потерять взаимную связь. Динамическое поведение платформы не доказывается встроенными проверками.

Git export использует cat-file --batch, чтобы export-ignore и export-subst не удалили и не изменили исходники. Создание review-ветки проверяет захваченные immutable blobs по SHA-256 прошедшего проверку кандидата и условно создаёт только новую ссылку при прежнем HEAD. Manifest-коммит с настоящими родителями удерживает входы от GC; журнал сессии остаётся отдельными файлами.

Межпроцессная блокировка защищает сохранение сессии от второго писателя. JSON заменяется через временный файл. Начальная подготовка до манифеста пока не является возобновляемой транзакцией — это описано пользователю.

## Производительность и измеренные пределы

Индекс точных путей и каталогов предков заменил квадратичный перебор правил перемещения. Постоянный тест сравнивает 300 случаев с фиксированным seed с простой эталонной реализацией, включая вложенные identity-границы.

Один предыдущий замер этапа сопоставления, без XML, Git и дискового ввода-вывода: 10 000 объектов по два пути — 22,864 с прежним алгоритмом и 0,0148 с индексом. Это не время обновления всей конфигурации.

Отдельный предыдущий замер XML на Windows/Python 3.12.14: 1000 полей + 1000 реквизитов — около 0,45 с и 31 МиБ tracemalloc; 5000 + 5000 — около 2,29 с и 153,5 МиБ. Заранее созданные входные bytes и нативная память не входят в этот пик. Большие формы требуют существенно больше памяти, чем их размер на диске.

Повторные чтения для проверки сохранности остаются заметной стоимостью. Кэш по одному mtime не заменяет проверку содержимого. rg/fd не используются как авторитетный список входов: их фильтры могут скрыть ресурсы.

## Подходы и инструменты

[Mergiraf](https://mergiraf.org/) полезен как пример структурного слияния с явными ключами и правилами допустимого порядка. Для интерфейса 1С порядок элементов не объявляется произвольным. [GumTree](https://github.com/GumTreeDiff/gumtree) даёт алгоритмы сопоставления деревьев; предметные ограничения 1С остаются отдельной задачей.

[Difftastic](https://github.com/wilfred/difftastic#can-difftastic-do-merges), delta, bat и fzf могут улучшать просмотр, но не являются доказательством правильного merge. [BSL Language Server](https://github.com/1c-syntax/bsl-language-server) рассматривается как независимая диагностика; его версия, требования и протокол ещё должны быть испытаны. Дополнительные native-программы не обязательны для запуска ядра.

## Перед выпуском

1. Прогнать линтер, unit-тесты и временные Git-сценарии; проверить актуальные настройки из поставляемых ресурсов.
2. Проверить создание, запись, чтение, замену, переименование и удаление в выбранном каталоге. При отказе не менять чужие ACL и не скрывать ошибку автоматическим выбором другого места.
3. Проверить пути с пробелами и кириллицей, старую кодовую страницу, коды завершения и отмену внешнего инструмента.
4. Проверить неизменность входов, index и старых веток; устаревший HEAD и кандидат должны блокировать новую ветку.
5. Собрать wheel и архив исходников. Установить wheel обычным pip в чистый venv и запустить модуль и созданный exe вне исходного дерева.
6. Исполнить примеры Python, загрузить TOML-примеры, проверить ссылки. Не заявлять о запуске реальной платформы без фактической проверки.
7. Спросить себя: понятен ли следующий шаг пользователю, можно ли продолжить после остановки, не потеряны ли изменения, оправданны ли время и память?

## Подтверждённые проверки

25 октября 2026 года: 233 теста прошли на Windows/Python 3.12.14, Ruff без замечаний. Wheel установлен в чистое окружение; модуль, pip-запускатель и TOML-шаблоны работают. Переносимая поставка проверена после распаковки ZIP из пути с кириллицей, пробелами и `&`, в cmd и Windows PowerShell, без Python в PATH и без доступного системного TEMP. Выполнены prepare, check с внешним Python/SSL-валидатором и создание review-ветки; исходный модуль, HEAD и index сохранены. Проверены состав исходного архива и SHA-256 файлов поставки. Настоящий отказ Windows ACL на создание подкаталогов проверен отдельно: программа сразу возвращает код 2 с пояснением; права проверочного каталога восстановлены.

Настоящие ERP/СППР, платформа 1С и Beyond Compare не запускались. Для них остаются платформенные и прикладные испытания на копии базы.
