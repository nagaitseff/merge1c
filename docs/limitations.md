# Границы поддержки версии 0.1

Целевой процесс — файловая выгрузка Конфигуратора, UTF-8 с BOM или без него, LF/CRLF и профиль платформы 8.3.27.2342. Правила XML проверяются на небольших независимых примерах формата 2.20. Испытаний на полной ERP, СППР и установленной 1С в среде разработки не проводилось.

## XML

Автоматически обрабатываются независимые свойства, известные коллекции формы, добавления, удаления неизменённых узлов и однозначные соответствия. Сохраняются исходные байты входящей версии вне принятых изменений.

ID элементов, реквизитов, команд и колонок учитываются в разных областях. Библиотека не перенумеровывает всю форму. При неизвестном способе числовой ссылки автоматическое переназначение прекращается.

Сложные переносы и неоднозначные переименования уже существующих элементов, одновременные изменения неизвестных составных структур и правки существующих XML-комментариев могут потребовать ручного решения. DTD, объявленные entities, неверный UTF-8 и чрезмерная вложенность отклоняются.

Роли, СКД, XDTO, обычные формы и бинарные макеты не имеют отдельных полноценных предметных движков в этой версии. Односторонние файловые изменения сохраняются; сложное одновременное изменение требует решения. Структурное совпадение XML не доказывает равенства прикладного поведения.

## BSL

Встроенный анализатор — лексический индекс методов и объявлений, а не компилятор 1С. Он умеет сохранять исходные фрагменты, сопоставлять методы, учитывать области и часть условных объявлений, обнаруживать дубли и объединять независимые изменения разных методов.

Разные изменения одного метода не склеиваются автоматически. Сложные изменения состава методов под препроцессором или директивами расширений требуют ручного решения. Анализатор не выполняет код, не проверяет все типы, контракты вызовов и синтаксис языка запросов.

Статическая связь события формы с методом проверяется по имени. Динамические обращения, наследование форм расширений и программное создание элементов могут потребовать контекста, которого нет в отдельных файлах. Проверка платформой и прикладные испытания остаются отдельным шагом.

## Файлы и Git

Все три входа должны быть согласованными снимками. Неизвестная старая поставка не восстанавливается угадыванием. Git-подготовка требует одного общего основания; criss-cross с несколькими основаниями пока отклоняется.

Символические ссылки, Windows junctions и submodules не поддерживаются. Состояние исполняемого бита на Windows берётся из известных Git-путей; полностью новый файл получает обычный режим. Конкурирующие изменения прочих файлов, включая бинарные, требуют ручного решения.

Готовый кандидат не применяется в текущую ветку автоматически. Публикация выполняется только созданием новой ветки с проверкой исходного HEAD. Перенос в master/develop и развёртывание базы — отдельные операции.

Rebase, подбор повторных исправлений задач для cherry-pick, перенос на EDT и подтверждённая поддержка 8.5 остаются дальнейшими этапами.

## Проверяющие программы

Готовность определяется сохранёнными настройками и фактически выполненными проверками. Библиотека не сообщает об успешном запуске платформы, когда та не запускалась. Отчёт внешнего адаптера должен соответствовать документированному протоколу.

Отпечаток инструмента включает executable и распознанные файловые аргументы. Это не полный снимок операционной системы, импортируемых библиотек или среды внешней программы. Проверка всего поведения произвольной конфигурации не обещается.
