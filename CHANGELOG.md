# Изменения

## 0.1.3

- Подготовка Git-сессии больше не переименовывает большие каталоги после выгрузки. Временный снимок используется по своему исходному пути; открытый XML больше не мешает этому переходу. Сбой WinError 5 воспроизведён на Windows с настоящим файловым дескриптором без FILE_SHARE_DELETE.
- Публичный экспорт сохраняет проверку пустого назначения и ограниченно повторяет переименование при временной блокировке Windows. Очистка временных снимков не скрывает первичную ошибку; оставшийся занятый каталог указывается в предупреждении.
- Git-данные и служебная ссылка сессии сохраняются до очистки временных снимков. Готовый результат остаётся Git-сессией даже при неудавшейся очистке.
- Во время выгрузки показываются сторона, число файлов и объём. После подготовки и создания review-ветки выводятся пояснения и следующие команды; JSON остаётся машинным.
- Руководство переписано вокруг обновления update/2.5.27.101 из vendor/2.5.27.101: от отдельных файлов кандидата до переноса проверенной review-ветки в update. Показаны схемы и ручной порядок проверки в 1С.

## 0.1.2

- Добавлены готовая переносимая Windows-поставка и скрипт сборки wheel, исходного архива и ZIP. Версии проверяются до сборки; TOML-шаблоны включены в поставку. Запускатель pip и автономная программа объяснены отдельно.
- Добавлен `storage.session_root` в проектный и локальный TOML. Параметр `--session` стал необязательным: новые сессии получают уникальные имена в выбранном каталоге.
- До создания снимков проверяются реальные операции записи, чтения, замены, переименования файлов и каталогов, удаления. `doctor --storage-only` позволяет проверить место хранения отдельно от Git и внешних программ.
- Проверка создания подкаталога сразу сообщает отказ Windows ACL, обходя длительные повторы стандартного tempfile при неточном os.access.
- Временные экспорты Git, файлы запуска инструментов и временный index создаются рядом с сессией или внутри неё.
- Шаблоны настроек содержат объяснение каждого параметра. `config --write-example` создаёт отдельный образец, даже если действующие настройки не читаются.
- TOML с BOM принимается; синтаксическая ошибка сопровождается строкой и указателем положения. Сессии 0.1.1 без новой настройки хранения остаются читаемыми.
- Документация сведена к основному руководству и трём справочным страницам: настройки, Python API, разработка и выпуск.

## 0.1.1

- Проверены PowerShell 5.1, PowerShell 7 и cmd с кириллицей, пробелами и внешним валидатором.
- Машинный вывод JSON использует ASCII-подстановки для защиты от старых кодовых страниц; файлы сессии остаются UTF-8.
- Добавлен `--quiet` для сценариев без вывода прогресса; уже включённый Git-коммит корректно возвращает JSON.
- Исправлены коллизии запланированных XML namespace, потеря перемещений комментариев и сравнение неизвестных числовых ссылок при remap ID.
- Неоднозначное локальное перемещение методов BSL теперь требует решения.
- Устранён квадратичный перебор правил переноса путей; сокращены повторные обходы при проверке сессии.
- Прямые Windows batch-обёртки отклоняются до запуска; поддерживаются явные интерпретаторы.
- Добавлены Ruff, проверки оболочек и новые регрессии.

## 0.1.0

- Python API и CLI для объединения трёх каталогов или снимков Git.
- Сохранение исходного XML, самостоятельные изменения свойств и вставки в прежние промежутки.
- Согласование ID формы по областям с переназначением коллизий наших добавлений.
- Консервативное объединение BSL по методам и проверка повторных объявлений.
- Сопоставление метаданных по контейнеру, типу и UUID, перенос связанных файлов при переименовании.
- Сессии, журнал, ручные решения и адаптер Beyond Compare.
- Внешние проверки, явный статус платформы и неизменяемый снимок настроек.
- Ветки-кандидаты с двумя родителями, CAS-проверки и закрепление входов от GC.
- Документация, демонстрационный пример и воспроизводимые измерения.
