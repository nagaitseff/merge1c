# Устройство библиотеки

## Отдельное предметное ядро

Библиотека работает с тремя снимками исходников. В ней нет сетки промежуточных слияний git-imerge: разбиение истории на маленькие шаги само по себе не определяет идентичность реквизитов и числовые ссылки формы. Сначала нужны предметные правила и независимая проверка результата. В дальнейшем их можно использовать внутри последовательного переноса коммитов.

## Компоненты

| Модуль | Назначение |
|---|---|
| `config.py` | Строгие настройки, профили, локальные пути и снимок политики |
| `xmlsource.py` | Разбор XML и байтовые диапазоны исходных фрагментов |
| `xmlmerge.py` | Трёхсторонние решения, размещение вставок, ID и известные ссылки формы |
| `bslmerge.py` | Индекс BSL и перенос методов с сохранением исходного текста |
| `engine.py` | Сопоставление файлов, UUID и связанных каталогов, проверка дерева результата |
| `gitrepo.py` | Git 2.50+, пакетное чтение объектов, предварительное слияние, закрепление входов и новая ветка |
| `session.py` | Снимки, решения, блокировка, проверки и восстановление |
| `tools.py` | Внешние программы с отдельными входами и кандидатом |
| `cli.py` | Команды, прогресс и вывод результатов |

## Идентичность объектов

Сопоставление метаданных учитывает контейнер конфигурации или расширения, вид объекта и его собственный UUID. UUID внутренних типов и другие вложенные значения не подменяют идентификатор самого объекта. При однозначном переименовании вместе с XML-описанием перемещается связанный каталог с модулями и ресурсами.

Путь и похожесть текста недостаточны. Разные типы объектов не объединяются только из-за общей XML-обвязки. Коллизии пути, UUID, rename/delete и rename/rename становятся явными замечаниями.

## Запись результата

Входящий файл является основой. Структурное сравнение определяет смысл изменения; запись использует исходные диапазоны байтов. Весь документ не пересериализуется.

Для вставки фиксируются логический родитель и прежние соседи. Новые входящие элементы в том же промежутке остаются первыми, затем идут наши добавления в исходном порядке. Если опоры утрачены или противоречат друг другу, положение не угадывается.

Согласование ID выполняется до применения изменений. Существующие свободные номера сохраняются. Переназначение относится к конкретной области и сопровождается проверкой известных ссылок. Повторный перенос той же дельты не должен создавать дубль.

## Независимая проверка

Проверяется всё выбранное дерево кандидата, включая файлы, которые не вызвали конфликта. Например, изменение XML-события и удаление его процедуры в BSL могут отдельно быть корректными и при объединении сломать связь.

Проверки исходников, структурные проверки, результаты внешних инструментов и проверка платформой учитываются отдельно. Статус готовности не выводится только из отсутствия маркеров или нулевого кода сторонней программы.

## Сохранение сессии

`session.json` записывается через временный файл и замену. `report.json` — производный отчёт. Команды изменения состояния используют межпроцессную блокировку и перечитывают состояние перед записью, чтобы старый объект Session не затёр чужое решение.

В Git отдельный manifest-коммит удерживает реальные родительские коммиты входов. Строки OID в JSON сами по себе не обеспечивают достижимость объектов для сборщика мусора. Изменяемый кандидат и журнал остаются на диске в каталоге сессии.

Создание ветки сверяет полный набор файлов и SHA-256 фактически записанных Git blobs со снимком, прошедшим проверки. Правка редактором между проверкой и захватом файлов не должна попасть в опубликованный коммит незамеченной.

## Стоимость операций

Сначала читаются карты файлов и их хеши. Неизменённые обычные файлы копируются без запуска отдельного Git-процесса на каждый файл. Экспорт коммитов выполняется потоком через `cat-file --batch`; атрибуты `export-ignore` и `export-subst` не могут убрать или изменить исходники.

XML-движок держит три структурных представления изменяемого документа. Это требует памяти, заметно большей размера самого XML. Сохранность и проверяемость имеют приоритет; измерения больших форм ведутся отдельно от маленьких тестов.

Правила переноса файлов индексируются по точному пути и каталогам предков. Для каждого файла не перебирается вся карта метаданных. Неизменённый вложенный объект может быть границей переноса своего родителя; эта семантика проверяется отдельно и сравнением с простой эталонной реализацией.
