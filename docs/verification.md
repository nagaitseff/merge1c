# Проверки проекта

## Проверка установки 25 октября 2026 года

В новом окружении `venv` на Python 3.12.14 выполнена обычная установка готового wheel через `python -m pip install --no-index --no-deps`. Из каталога за пределами исходного проекта проверены `python -m merge1c --version` и созданный pip файл `Scripts/merge1c.exe --version`: оба вывели `merge1c 0.1.1`. Проверена и команда определения пути к созданному exe из инструкции по установке. PATH и основной Python пользователя не менялись.

Это отдельная проверка механизма установки; запуск на Python 3.14 с другого компьютера ею не подтверждается. Ошибка `No module named merge1c` на предоставленном скриншоте означает, что выбранный там интерпретатор не находит пакет.

## Версия 0.1.1: повторный аудит

Заключительный полный прогон: **218 тестов, 67,685 секунды, ошибок нет**. Ruff 0.17.2: `ruff check src tests examples` — без замечаний. Пять примеров Python из документации исполнены; локальные ссылки и совместимость синтаксиса с Python 3.11 проверены.

Отдельные интеграционные сценарии прошли в настоящих Windows PowerShell 5.1, PowerShell 7.6.5 и cmd. Проверялись кириллица, пробелы, `&` в пути, захват JSON через старую кодовую страницу, внешний Python-валидатор и коды 0/1/2. Режим `--quiet` также прошёл в PowerShell 5.1 с `$ErrorActionPreference = 'Stop'`. Подробности — в [инструкции по оболочкам](windows.md).

Повторный аудит выявил и закрыл коллизии запланированных XML-префиксов, потерю перемещений комментариев, несогласованность числовых ссылок вида `01`/`+1`/`1` и незаметную потерю локальной организации методов BSL. Эти случаи стали постоянными регрессионными тестами. Во время проверки неизменности index также исправлен сам тест: его вспомогательный `git status` мог обновлять fsmonitor-данные, поэтому чтение теперь выполняется без необязательных блокировок.

Устранён квадратичный перебор правил перемещения путей. Измерялось только сопоставление, без XML, Git и файлового ввода-вывода; на каждый объект приходилось два пути:

| Объектов | Прежний перебор | Индекс путей |
|---|---:|---:|
| 1000 | 0,173 с | 0,0012 с |
| 5000 | 4,535 с | 0,0068 с |
| 10 000 | 22,864 с | 0,0148 с |

В постоянный тест включены 300 случаев с фиксированным seed: вложенные объекты, связанные модули, неизменённые вложенные пути и повторные правила. Результат нового алгоритма сравнивается с простой прежней реализацией; проверка не зависит от скорости машины.

На искусственном дереве из 250 объектов / 500 файлов число хеширований во время `check` сократилось с 8000 до 6000, при подготовке — с 11000 до 10500. Между командами не используется кэш, основанный только на времени изменения файла. Основной оставшейся стоимостью на такой нагрузке являются повторные проверки файлов; время полной ERP пока не измерено.

Ни один из этих результатов не подтверждает загрузку конфигурации настоящей 1С или работу установленного Beyond Compare. Скачан только Ruff как инструмент разработки; остальные рассмотренные программы не добавлены в обязательные зависимости.

## Версия 0.1.0: исходная проверка

Дата: 24 октября 2026 года. Окружение: Windows 11, Python 3.12.14, Git 2.53.0.windows.3.

## Тесты

```powershell
python -m unittest discover -s tests -q
```

Заключительный полный прогон: **193 теста, 62,099 секунды, ошибок нет**. Это результат на машине разработки, а не обещание времени на другой системе. Отдельных прогонов на Python 3.11, Linux и macOS пока не было.

Проверки охватывают XML и BSL, настройки, внешние программы, команды и временные репозитории Git. Среди интеграционных сценариев:

- Два последовательных обновления существующего develop с сохранением его истории и продолжающихся работ.
- Сохранение исходных байтов при BOM, CRLF, кириллице, комментариях и разных префиксах пространств имён.
- Добавление реквизитов и элементов формы обеими сторонами, коллизии ID в отдельных областях и повторный перенос без дубля.
- Несвязанные типы метаданных с похожей XML-обвязкой, перемещение объекта с его модулем, коллизии файлов и каталогов.
- Сохранение исходного index и рабочего дерева, запрет публикации при изменении HEAD и при активном merge.
- Проверка именно захваченных Git blobs: изменение кандидата после проверки не публикуется как проверенный результат.
- Удержание входных коммитов от GC, условное освобождение только собственной служебной ссылки.
- Отмена и тайм-аут внешней команды, неверный отчёт, изменение проверяющего скрипта, неподходящая версия платформы в отчёте.

Тесты внешних программ используют небольшие самостоятельные команды Python. Они проверяют протокол запуска, но не заменяют проверку настоящего Beyond Compare или Конфигуратора.

## Установка и пример

Проверены сборка wheel без сети и зависимостей, установка в отдельный каталог и импорт установленной библиотеки за пределами исходного дерева. Пример `examples/demo.py` создаёт форму и модуль, выполняет объединение и проверяет порядок полей, уникальность ID, комментарий, BOM и CRLF.

## Производительность XML

Измерения выполняются отдельно от обычных тестов:

```powershell
python examples/benchmark.py --records 1000
python examples/benchmark.py --records 5000
```

В каждой коллекции обе стороны добавляют по 20 узлов. Используются пространства имён формы, кириллица, BOM и CRLF. В обоих случаях разрешено по 80 коллизий числовых ID; сохранность остальных байтов входящей стороны проверена сравнением.

| Полей и реквизитов | Размер входящей формы | Обычное время | Пик tracemalloc |
|---|---:|---:|---:|
| 1000 + 1000 | 431 820 байт | 0,45 с | 31,139 МиБ |
| 5000 + 5000 | 2 128 881 байт | 2,29 с | 153,498 МиБ |

Время и память измеряются разными запусками. Трассировка памяти сама замедляет программу. Указанный пик относится к отслеживаемым Python-выделениям во время merge, не включает заранее созданные входные байты и не равен полной памяти процесса.

Эти значения не включают Git, сканирование всей конфигурации, работу платформы, обновление базы и прикладные испытания. На больших формах расход памяти остаётся существенным; параллельный запуск без измерения доступной памяти не является готовой оптимизацией.
